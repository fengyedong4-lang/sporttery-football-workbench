# v4字段与校验说明

## 适用范围

本说明和v4模板只面向规则实施后的新预测记录。`data/prediction_history.json`中的既有记录不迁移、不补字段、不重算；历史四玩法记录继续按冻结时的实际玩法统计。旧每日脚本及其导出物属于归档，不重跑，也不要求改造成v4。

`data_structure_template.json`是字段定义基准。`templates/赛前预测模板.json`与其中的`prediction_sets[0]`深复制一致，保留原完整字段及旧脚本常用的兼容字段。新代码应直接读取v4字段，不再使用旧简版`result/handicap_result`映射。

## 预测集和版本

- `schema_version`固定为`4`。
- 模板默认`state=draft`，预测值为`null`，不得把示例值当成确认事实。正式记录改为`formal`后，必须填写`generated_at`、`finalized_at`、`freeze`和64位`snapshot_hash`，且时间早于最早一场开赛。
- `prediction_scope`默认仅含`result`、`handicap_result`。
- V1的`parent_version`为`null`。V2及以后引用上一版本，并在`amendment`记录`事实更新`、`录入纠错`或`重新评估`、原因、证据、时间和字段差异。
- 主统计按日期和比赛编号选择开赛前合法`finalized_at`的最高`formal`版本。任一同版本出现不同正式记录必须报冲突，不按时间择优；新版本缺少的玩法不从旧版补齐。

## 玩法状态与唯一选项

`prediction.play_status`分别记录两种玩法，状态枚举为：`已确认`、`未开售`、`待核实`、`无法获取`、`未请求`、`不适用`。

只有`已确认`状态可以保存唯一正式选项和置信度，并将玩法写入`prediction_plays`。其他状态的`selection`及兼容字段必须为`null`，玩法不得写入`prediction_plays`，正式记录还要填写`reason_unavailable`。兼容字段`predicted_result`、`predicted_handicap_result`必须与对应`selection`一致。

胜平负枚举为`胜/平/负`，让球胜平负枚举为`让胜/让平/让负`；置信度为`低/中低/中/中高/高`。`predicted_score`和`predicted_total_goals`在新记录中必须为`null`，`score`、`total_goals`不得进入`prediction_plays`。

## 概率和让球判断

`three_way_probabilities.home/draw/away`必须同时为0至100的数值且合计100，或同时为`null`并填写`reason_unavailable`。有数值时必须说明`method`，并保存证据核对时间和估计时间；主观概率不得冒充训练或校准模型输出。

设`d`为主队90分钟进球数减客队90分钟进球数，`h`为中国体彩官方主队让球数。`handicap_assessment`统一按以下三段判断：

- `d+h>0`：让胜；
- `d+h=0`：让平；
- `d+h<0`：让负。

这套表达同时适用于主让1球、主受让1球、主让2球及0球。官方让球未知或不是整数时不得保存让球正式选项。两项正式结果必须至少存在一个整数`d`可以同时满足。

## 规则应用证据

`rule_application_timeline`保存独立判断、读取规则、应用规则和保存对照的时间。每场`rule_application_comparison.before`必须引用规则应用前已落盘的独立判断文件及其SHA-256，`after`记录应用后的结果、置信度和证据。所有时间必须早于开赛，`created_pre_match`和`no_post_match_backfill`必须为`true`。校验器会实际读取引用文件并核对hash；文件缺失或hash不一致都不能通过。

## 来源、精选与赛后状态

可变事实来源保存`published_at`、`checked_at`和确认级别；体彩字段另存官方来源及核对时间。正式赛前记录中的来源、概率、判断和规则对照时间均不得晚于开赛。

新预测集可直接在`relative_picks.items`保存精选；若正式版本已经冻结，使用独立补充文件，并在`relative_picks_supplement_ref`保存补充记录、创建时间和引用的正式版本。精选只引用已有正式选项，不改变预测方向。

`final_result.fact_confirmation`记录90分钟赛果事实是否已核实；`official_settlement`单独记录体彩官方结算。外部可靠赛果可支持90分钟命中分析，但不得标成体彩官方结算。延期、中止、取消、待补赛、90分钟未确认及未开售玩法不进入当前分母。

赛后`review_action.action`从`新增候选规则`、`为既有规则补证`、`待验证假设`、`暂不调整`中选择。每场不强制新建规则，必须保存相应依据。

## 校验器

校验器只读文件，不修改模板或历史数据：

```powershell
python scripts/validate_prediction.py templates/赛前预测模板.json --mode draft
python scripts/validate_prediction.py path/to/new_v4_prediction.json --mode formal
python scripts/test_validate_prediction.py
```

旧schema输入会显示`SKIP`，表示未按v4校验，不表示v4合格。代码还提供：

- `select_effective_versions(records)`：选择同日同编号最高的合法赛前正式版本，重复版本冲突时报错；
- `statistics_eligibility(record, play)`：按冻结玩法、90分钟确认、比赛完成状态及未开售状态判断是否进入分母。
