# 历史预测

关闭页面或服务后，预测记录仍保存在磁盘。重新启动工作台，进入左侧“历史预测”，选择日期、类型或队伍关键词，点击“查看完整批次”即可阅读当时结果。无需重新预测，不调用模型、不取证、不复盘。

## 三类存档

1. **候选草稿**：`runtime/drafts/*.json`，每次预测完成后保存的独立批次，包括失败或证据不足时实际保存的结果。
2. **权威正式版本**：项目根 `data/prediction_history.json` 的全部 `records`，按原预测日期与版本分组。保留旧版本、重复记录、未知字段；这里不进行“最高合法版本”筛选，也不据此汇总命中率。
3. **赛前原始存档**：项目根 `exports/**/prediction_V*.json` 的原始导出，排除备份目录。兼容 `matches`、`records` 和 `prediction_sets`；含多个集合时按集合列出，详情仍保留完整源文件 JSON。

三类记录可能描述同一比赛及版本，因此分别计数。原始存档是赛前证据，正式历史可能已补充赛后字段，不能互相覆盖。旧版比分与总进球仅展示原记录，不恢复为新预测输出。

## 查询和详情

- 类型切换立即生效；日期、关键词和精确赛事名在点击“筛选”后生效。
- 日期匹配原预测日期或北京时间保存日期。关键词查队伍、竞彩编号、赛事或批次标题。
- 一个场次命中筛选就展示它所在批次；打开后仍显示该批次的全部比赛。
- 每页20批，提供上一页/下一页；清除筛选可找回最早的记录。
- 详情展示原两玩法、让球、状态、理由、反证、已有概率及证据。原始 JSON 保留无法映射的遗留字段。
- 无法读取的文件会显示警告，不因一个坏文件隐藏其他有效批次。

## 只读接口

`GET /api/prediction-history`

参数：`kind=all|draft|formal|export`、`q`、`date_from`、`date_to`、`competition`、`page`、`page_size`（1—100）。返回分页批次、全库分类型计数及读取警告。

`GET /api/prediction-history/{kind}/{id}`

返回批次完整原记录与 `read_only=true`。详情ID只在已枚举的合法批次中匹配，不能指定任意文件路径。所有查询均不写入索引或源文件，不联网。

浏览历史不改变正式统计口径。需要赛后评价时进入“复盘与模型”，选择对应批次再手动运行复盘。
